# Knowledge — Plateful (Capacitor / Web)

Gemeinsames Repo-Wissen für alle Agenten (Claude Code, Codex, Cloud-Sessions) und Menschen: Gotchas, Mechanismen, getroffene technische Entscheidungen. Ein Fakt pro Datei; bei Änderung die Datei und ihre Zeile hier aktualisieren, Erledigtes löschen. Persönlicher Kontext, Produkt-/Markenentscheidungen und Projekte liegen im PersonalOS (`~/PersonalOS`), nicht hier. Architektur und Betrieb stehen in `AGENTS.md`.

- [E2E tests never reach the backend](e2e-never-reaches-the-backend.md) — until 2026-10-05 CI ran Playwright against the production project URL; since the profile moved to `rpc/get_current_profile` (2026-07-26) the unmocked call made 53 of 65 tests time out, CI was red for ten weeks and each push sent ≈ 280 refused requests to production; now the suite starts its own dev server on port 5174 with a backend host that cannot resolve, the `backendGuard` fixture fails any test whose request has no mock, and every spec imports from `./fixtures`; add the mock when the app calls something new, never loosen the guard
- [The E2E dev server mounts no React Query devtools](e2e-no-query-devtools.md) — since 2026-10-07 `playwright.config.ts` passes `VITE_E2E=true` and `src/main.tsx` mounts `ReactQueryDevtools` only without it; the devtools' bottom-right toggle sat on the bottom navigation's Planner link at the Pixel 5 viewport and made the cookbook→planner test fail on every `Mobile Chrome` run; do not switch the server to another Vite mode (PostHog is skipped only in `development`) and do not `force: true` a click past an overlay
- [Daily ops health check](ops-health-check.md) — since 2026-10-05 the Claude cloud routine "Plateful Health-Check (täglich)" (`trig_016p78o9moDVxxe6ww9ZRnff`, 06:30 UTC, prompt and SQL live in the routine) reads project status, 22 database checks (worker alive, failed and looping pg-boss jobs, cron, pg_net, sizes, connections, slots, imports, compute size), Postgres and API error logs, the security advisor and the extractor's health; green is silent, a finding becomes one Todoist task in 🥗 Plateful → Backlog due that day (Kerim's standing exception); a daily review, not an alarm; its first finding (2026-10-07, the connection-limit incident) became the Backlog task as designed; the Supabase connector it uses is not read-only
- [Supabase "Disk IO budget" warning](supabase-disk-io-budget.md) — warned 2026-10-04 while the project was still on Nano compute (≤ 0.5 GB RAM, despite Pro since 09-10); Postgres' own IO was negligible (217 MB database, cache hit 100 %, ≈ 63 MB WAL a day), so memory pressure and swap are the likely cause but unverified (dashboard charts not seen); Kerim resized to Micro 2026-10-05 ≈ 14:15 UTC (≈ 4 min down, everything reconnected by itself, all pg statistics reset); the alarming `temp_bytes` of 469 GB since May is one ≈ 3 MB file a minute — every read of `pg_stat_statements` spills to a temp file once the view outgrows `work_mem` (reproduced), most likely Supabase's own metrics exporter; harmless
- [Supabase connection limit](supabase-connection-limit.md) — 60 direct connections on Micro (57 for non-superusers; Realtime wants 12 free), shared by the extractor's pg-boss pool (10), Realtime (7), PostgREST, Storage through the DB host's PgBouncer (≥ 21 under load, idle ones held 600 s) and pg_cron; exhausted 2026-10-06 17:54–18:04 UTC when Kerim's Android cookbook open (454 recipes → ≈ 900 per-card requests and 190 cover fetches from 76 Storage instances) met three running imports; no user error, five cron runs refused and caught up, Realtime off for minutes; fixed 2026-10-07: the cookbook list carries `image_path`, one household-wide `meal_planning` read feeds every card's plan status and the sort, covers load lazily, and `RecipeCard` makes no request of its own; Kerim ruled out more compute, with this few users the limit is a bug, not capacity
- [Sign in with Apple on the web](apple-sign-in-web.md) — since 2026-09-30 `SignUp` offers Apple on the web (not Android) through the same ID-token flow as Google, so Apple-ID users from iOS get through the MCP consent screen; needs the Services ID `com.kblanks.plateful.web` registered at Apple with Return URL `https://app.plateful.cloud/signup`, listed next to the bundle ID in Supabase's Apple Client IDs, and `VITE_APPLE_SERVICES_ID` in Vercel (unset = button hidden); no Secret Key, no localhost, name arrives only on the first authorization
- [OAuth consent after email sign-in](oauth-consent-login-redirect.md) — password sign-in from `/oauth/consent` reaches `/signup/email`; its signed-in guard must route through `/` so `PostSignInLanding` can resume the saved `authorization_id`, otherwise review users land on Home and the MCP connection stalls
- [RevenueCat webhook: sandbox never touches production](revenuecat-webhook-sandbox-guard.md) — since 2026-09-24 a `SANDBOX` event is dropped when the user's row is `PRODUCTION` (a sandbox TRANSFER from a device test had overwritten Kerim's real subscription row and paywalled his household on trial-conversion day); sandbox rows of test accounts are still written; one sandbox tester Apple ID per test account, never Restore under a test account on a phone with a real subscription
- [Account deletion worker](account-deletion-worker.md) — durable job Auth → PostHog → RevenueCat since 09-24 (version 14; Auth first so clients sign out at once, web/iOS show one confirmation, no status polling), pg_cron drain every 2 min; PostHog bulk_delete is ASYNC since 2026-09 (`persons_queued_for_deletion`, deleted stays 0), worker accepts deleted+queued == found since f80999d / version 13; deploy via MCP with the three `functions/...` files; job FK `set null` keeps it alive after the Auth delete; stuck provider steps are now invisible to users, check the table in maintenance
- [`randomId()`, never `crypto.randomUUID()`](random-id-not-crypto-randomuuid.md) — `crypto.randomUUID` is secure-context-only and went missing on a real Galaxy S24 Ultra (WebView 131, `https://localhost`, 2026-09-17), throwing inside a `useState` initializer and taking the dialog down; `src/utils/randomId.ts` falls back to `getRandomValues` then `Math.random`, all six call sites converted — never call `crypto.randomUUID()` directly, and don't use `randomId` for anything that must be cryptographically strong
- [Chatbot memory lives in Redux](chatbot-memory-in-redux.md) — the "change a saved recipe → new-recipe duplicate" bug was client state, not the model: `knownRecipeIds`, unsent `[Proposal Outcomes]` and the proposal counter were page state and reset on every navigation while the conversation survived, so the edge function rejected correct edits; since 2026-09-23 all three live in `chatbotSlice` and `resetChat` clears them together
- [Edge-function models and reasoning](edge-function-models.md) — chatbot = `gpt-6-sol` (since 2026-09-23, Terra before) with `reasoning: { effort: "low" }` and a one-shot retry without `previous_response_id`; search parser = `gpt-6-luna` (since 2026-09-23) with `reasoning_effort: "none"`; both since 2026-09-10 (gpt-5.4-nano before); `scripts/chatbot-model-eval.ts` scores the chatbot's edit-vs-new tool choice per model; never pass `temperature` to a gpt-5 model; the privacy policy names providers per feature, not models, so a provider switch needs a policy update first; deploy via the Supabase MCP `deploy_edge_function` (no CLI on the Mac), files listed in the note
- [`signed_in` after identify](signed-in-after-identify.md) — `pendingSignIn.ts` (2026-09-11): call sites mark the method, `fetchUserData` spends it right after a successful `posthog.identify()` (person props freeze at ingestion), sign-out clears it; magic link = fragment token remembered at load and matched against the session the auth listener reports (web), or marked in `AppUrlListener` (Android App Link); NEVER trigger on Supabase's `SIGNED_IN` alone (fires on session recovery + tab focus); in-memory, a reload before identify loses it
- [Android: R8 im Release-Build](android-r8.md) — seit 2026-09-13 `minifyEnabled true` + `shrinkResources true` + `proguard-android-optimize.txt`, weil Play ab Februar 2027 je 25 % Optimierung/Verschleierung/Schwund bei > 10 MB DEX verlangt (Plateful: 39 MB); `optimization.keepRules.ignoreFrom('com.revenuecat.purchases:purchases-store-amazon')` ist Pflicht, weil dessen Consumer-Regeln ein globales `-dontoptimize` mitbringen (sonst 0 % Optimierung); Werte aus `BUNDLE-METADATA/com.android.tools/r8.json` der AAB lesen; Mapping liegt in der AAB, nichts hochladen; AGP 9 nicht nötig und durch RevenueCats Plugin blockiert
- [Play Console: die drei empfohlenen Aktionen](play-console-warnings.md) — Edge-to-Edge-Warnung kommt allein aus `@capacitor/status-bar` (abgekündigte `Window.setStatusBarColor`-Aufrufe in Methoden, die wir nicht nutzen; Ionic: not planned), verschwindet nur ohne das Plugin; Mapping-Hinweis erledigt sich durch R8 von selbst; native Symbole gibt es nicht, weil `libandroidx.graphics.path.so` (Compose via RevenueCat UI) gestrippt ausgeliefert wird, `debugSymbolLevel` extrahiert nichts
- [Review accounts: hidden password sign-in](review-accounts.md) — Google rejected 1.1 twice for a "paywall" the reviewer could not get past because magic link and Google Sign-In are both unusable for them; since 2026-09-16 typing a review address in `/login` or `/signup/email` reveals a password field (`src/lib/reviewSignIn.ts`, mirrors iOS `AuthStore.reviewEmail`); `androidreview@` for Play, `chatgptreview@` for OpenAI's plugin reviewers, `claudereview@` for Anthropic's connector reviewers and `musereview@` for Meta's Muse connector reviewers, who hit the same dead end at `/oauth/consent` when connecting the MCP server; own account and household each, premium is a never-expiring `environment = 'MANUAL'` row and the gate is `household_entitlements`, not the RevenueCat SDK; re-seed with `node scripts/seed-review-account.mjs android|chatgpt|claude|muse` in the iOS repo; Play Console instruction text in the note
