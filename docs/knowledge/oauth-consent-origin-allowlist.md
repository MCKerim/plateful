# OAuth consent: Supabase checks the request Origin

**Failure (2026-10-23 and 2026-10-24):** Connecting the ChatGPT connector from the Android app (Celine, Galaxy S25 / SM-S931B, Android 16, build 46) opened `/oauth/consent?authorization_id=…` in the app as intended, and the page showed "Diese Verbindungsanfrage ist ungültig oder abgelaufen" (`loadFailed`). Auth logs: every `GET /auth/v1/oauth/authorizations/{id}` from the app's WebView (UA `; wv)`, referer `https://localhost/`) answered `400 unauthorized request origin` (`error_code: validation_failed`), seven attempts over the two days. The same call from Safari on iPhone and from the web returned 200 and the connection completed.

**Mechanism:** Supabase Auth runs `validateRequestOrigin` (`internal/api/oauthserver/authorize.go`) before `GET /oauth/authorizations/{id}` and `POST /oauth/authorizations/{id}/consent`. An empty `Origin` header passes (native HTTP clients). A non-empty one must pass `IsRedirectURLValid`: same scheme and hostname as the Site URL (`https://app.plateful.cloud`), or a match in the Redirect URLs allow list. The Capacitor Android WebView serves the bundle from `https://localhost`, so its Origin is `https://localhost` and fails both. Browsers pass because their origin is the site URL. The iOS app is unaffected: the AASA does not claim `/oauth/consent`, so Safari opens it.

**Fix:** add `https://localhost` to Authentication → URL Configuration → Redirect URLs of the Supabase project. Added 2026-10-24 (7 entries now). Confirmed the same day: Celine's next attempt at 15:47 UTC answered 200 on the details call, 200 on the consent POST and 200 on ChatGPT's token call four seconds later (a bare probe cannot show this, the route checks the user JWT before the origin). No code change; the Android build already sends the right request, and the consent POST goes through the same check. Do not move the WebView origin instead (Capacitor `server.hostname`): localStorage, and with it the Supabase session, is per origin, so that would sign every Android user out. Opening consent in the system browser instead would demand a web sign-in the person usually does not have.

**Return to ChatGPT:** after approval the page sets `location.href` to ChatGPT's redirect URL inside the WebView; Capacitor hands that navigation to the system, and ChatGPT redeemed the code (token call in the logs), so the round trip works on Android.
